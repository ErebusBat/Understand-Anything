## Integration work the issue does not account for

1. **Typed dependencies need an end-to-end contract.** `batchImportData` tells the analyzer to emit every entry as `imports`; merge recovery also hardcodes `imports`. Adding associations directly to that map would mislabel them, and could produce duplicate `imports` plus `depends_on` edges. Prefer preserving explicit `importMap` and adding typed dependency facts alongside it; derive the union for community detection and neighbor context. Persist those facts through scanning, batching, and deterministic merge recovery. [Analyzer contract](https://github.com/Egonex-AI/Understand-Anything/blob/b8c807c632743ab695ec43cb654a0f1efe216bc8/understand-anything-plugin/agents/file-analyzer.md#L264-L303), [batch payload](https://github.com/Egonex-AI/Understand-Anything/blob/b8c807c632743ab695ec43cb654a0f1efe216bc8/understand-anything-plugin/skills/understand/compute-batches.mjs#L569-L615), [merge recovery](https://github.com/Egonex-AI/Understand-Anything/blob/b8c807c632743ab695ec43cb654a0f1efe216bc8/understand-anything-plugin/skills/understand/merge-batch-graphs.py#L1066-L1133).

Existing refresh combines old and new `importMap` entries, and pruning removes refreshed `imports` edges only. ## Root directories and `lib`

Rails normally treats existing `app` subdirectories as roots, excluding assets, javascript, and views, and incorporates engine roots. A root represents `Object`; `app/models/admin/user.rb` implies `Admin::User`, not `Models::Admin::User`. `lib` is not intrinsically an autoload root. Rails 7.1+ offers `config.autoload_lib(ignore:)` and its once-loader counterpart; applications may explicitly enable them. Configuration can also live in environment files and engines. [Rails autoload guide](https://guides.rubyonrails.org/autoloading_and_reloading_constants.html#config-autoload-paths), [lib configuration](https://guides.rubyonrails.org/autoloading_and_reloading_constants.html#config-autoload-lib-ignore).

Rails 8.0.2's engine configuration uses the app glob `{*,*/concerns}`; do not recursively make every descendant its own root. Its `lib` entry is a Ruby load path, which is a different concept. [Pinned Rails configuration source](https://github.com/rails/rails/blob/v8.0.2/railties/lib/rails/engine/configuration.rb).

Zeitwerk treats nested roots independently: `app/models/concerns/trackable.rb` normally defines `Trackable`. It can create an implicit namespace without a corresponding `.rb` file; custom root namespaces, collapsed directories, and ignored files change mappings. Duplicate constants in different roots can be shadowed according to loader order. [Zeitwerk nested roots](https://github.com/fxn/zeitwerk#nested-root-directories), [implicit namespaces](https://github.com/fxn/zeitwerk#implicit-namespaces), [custom root namespaces](https://github.com/fxn/zeitwerk#custom-root-namespaces), [collapse](https://github.com/fxn/zeitwerk#collapsing-directories), [shadowing](https://github.com/fxn/zeitwerk#shadowed-files).

**Constraint:** retain root identity and configuration provenance. Never guess duplicate precedence from filesystem sorting. Missing engine sources, unsupported loader customization, or unknown root ordering must remain visible limitations. A namespace directory alone is not a file dependency target.

## Ruby lookup: FQN indexing is necessary but insufficient

Ruby documents different nesting for `module A; module B` versus `module A::B`: the latter does not introduce `A` into lexical nesting. Leading `::` explicitly requests a top-level constant. Classes also inherit constants. [Ruby nesting and constant scope](https://docs.ruby-lang.org/en/master/syntax/modules_and_classes_rdoc.html#label-Constants), [inheritance](https://docs.ruby-lang.org/en/master/syntax/modules_and_classes_rdoc.html#label-Inheritance).

**Constraints/inferences:**

- Record lexical nesting from the AST; do not reconstruct it by splitting a declaration's qualified name. A compact namespace must not gain synthetic enclosing scopes.
- A globally unique basename is insufficient: a lone `Admin::User` does not make bare `User` accessible at top level. Conversely, two `User` basenames need not be ambiguous when lexical scope selects one.
- Distinguish `::Admin::User`, relative `Admin::User`, and bare `User`; a `::` separator alone does not make the reference absolute.
- A useful restricted resolver can search known lexical candidates, but unknown ancestors/mixins can affect fallback. Mark such cases unresolved or heuristic; do not claim complete Ruby semantics.
- Track constant assignments/aliases and reopened definitions as potential shadowing/multiple-definition cases. Treating every capitalized token as a class reference creates false edges.

## Static configuration parsing without application execution

Ruby provides parser APIs that return syntax trees; parsing source is distinct from executing it. [Ripper documentation](https://docs.ruby-lang.org/en/master/Ripper.html). This fork already loads the Ruby tree-sitter grammar successfully; extend that existing parsing path rather than introducing a Ruby runtime requirement.

**Proposed safe subset, not a Rails guarantee:** recognize AST shapes for literal arrays/strings, `%w`, `config.autoload_paths << ...`, literal `+= [...]`, `config.autoload_once_paths`, and supported `config.autoload_lib(ignore: ...)` calls. Resolve an allowlisted root expression such as `Rails.root.join("app", "services")` by constructing a path in the analyzer, never by invoking Ruby. A literal relative string still needs its configuration context established.

Do not `eval`, `require` configuration, run `rails runner`, or eager-load the application to discover dependencies. Do not execute `Dir.glob`, user helpers, interpolation, or environment conditionals. If implementing glob interpretation later, use bounded filesystem matching under the analyzed checkout. Recognize unsupported constructs and record their locations; silent fallback to defaults can fabricate edges where configuration removes or ignores roots. Parse relevant environment/initializer/engine sources only with known context, or report incomplete coverage. Prevent paths or symlinks from silently escaping the selected analysis boundary.

## Inflections and acronyms

Rails filename mapping uses camelization and allows both global acronyms and loader-specific basename overrides; a custom inflector can replace the behavior. [Rails inflection customization](https://guides.rubyonrails.org/autoloading_and_reloading_constants.html#customizing-inflections). ActiveSupport additionally supports irregular, uncountable, plural, and singular rules; custom rules take priority. [Inflections API](https://api.rubyonrails.org/classes/ActiveSupport/Inflector/Inflections.html).

**Constraint:** keep filename camelization separate from association singularization. Do not lowercase constants or strip a trailing `s` as a substitute. Minimum fixtures should include `html_parser`/`HTMLParser`, `people`/`Person`, and an uncountable. Literal acronym/override declarations are tractable; arbitrary regex rules or custom inflector methods require deliberate support or unresolved diagnostics. AST declarations can corroborate expected file names, but mismatches must not be silently accepted as valid Zeitwerk mappings.

## ActiveRecord associations

The API supports `class_name` overrides for direct associations. `through` uses another association's source reflection, ignoring its own `class_name`; `source` selects that association, while `source_type` disambiguates a polymorphic source. A polymorphic `belongs_to` takes its actual class from persisted type data. Therefore `belongs_to :attachable, polymorphic: true` must not invent an `Attachable` target. The inverse `has_many :pictures, as: :imageable` can still have a definite `Picture` target. [Association API and options](https://api.rubyonrails.org/classes/ActiveRecord/Associations/ClassMethods.html).

Pinned source shows that default names are singularized **only for collection associations**, then camelized. Association resolution invokes the owner model's `compute_type`. [Rails 8.0.2 reflection source](https://github.com/rails/rails/blob/v8.0.2/activerecord/lib/active_record/reflection.rb). That method searches candidates derived from the model's name and honors leading `::`; it is not the lexical lookup of a Ruby expression at the DSL call site. [ActiveRecord compute_type](https://api.rubyonrails.org/classes/ActiveRecord/Inheritance/ClassMethods.html#method-i-compute_type).

**MVP recommendation:** support literal direct `belongs_to`, `has_one`, `has_many`, and HABTM names/options; require a known local model target. Gate recognition to model/concern contexts to avoid treating arbitrary similarly named methods as AR facts. Preserve macro/option/source evidence on `depends_on` relationships where the schema permits. Defer `through` target inference unless the intermediate and source associations are explicitly resolved; dynamic options and unknown polymorphic targets remain unresolved. Do not add a join-model node for HABTM merely because a join table exists. Association edges do not imply method-call edges.

## Include, extend, and concerns

`include` supplies module instance methods to the including class/module. `extend` supplies those methods to the receiver object, commonly the class object; it is not ordinary superclass inheritance. [Ruby Module](https://docs.ruby-lang.org/en/master/Module.html#method-i-include), [Ruby Object extend](https://docs.ruby-lang.org/en/master/Object.html#method-i-extend). ActiveSupport::Concern manages dependent modules and included/class-method callbacks. [Concern API](https://api.rubyonrails.org/classes/ActiveSupport/Concern.html).

**Constraint:** use the constant resolver for explicit mixin arguments, preserving `include` versus `extend` evidence. Prefer a dependency relation unless the existing schema explicitly defines `inherits` to include mixins; the commenter's suggestion is not a Ruby semantic equivalence. Keep concern-to-concern edges; defer simulating callback injection or attributing all concern-defined associations to every host.

## Routes and test conventions

Rails routes are Ruby DSL code. `namespace` affects controller modules and URL paths, while `scope module:` and path-only scopes differ. A singular `resource :geocoder` still targets plural `GeocodersController` and omits the index action. [Routing guide](https://guides.rubyonrails.org/routing.html#singular-resources), [scope semantics](https://guides.rubyonrails.org/routing.html#controller-namespaces-and-routing).

**Recommendation:** defer routes from day one. A later subset can accept immediate statements in the recognized routes `draw` block: literal HTTP verb plus `to: "controller#action"`, and option-free `resources`/`resource`. Do not flatten nested scopes, conditionals, mounts, concerns, or drawn files into top-level routes. Controller overrides and `only`/`except` must be implemented or rejected explicitly. Declared routing does not prove a locally defined action method exists.

Rails defaults to Minitest and generates `test/models/article_test.rb` alongside `app/models/article.rb`. [Rails testing guide](https://guides.rubyonrails.org/testing.html#writing-your-first-test). RSpec documents type-based directories such as `spec/models`, `spec/controllers`, and `spec/requests`; request directories may also be named `integration` or `api`. [RSpec directory conventions](https://rspec.info/features/7-1/rspec-rails/directory-structure/).

**Constraint:** exact relative-path pairing after removing `_test` or `_spec` is a convention heuristic, not proof of coverage. Require both files to exist and preserve namespaces. Do not apply the same mapping indiscriminately to request/system/integration tests, shared examples, or helpers. The local linker's verified `tested_by` direction is production → test.
